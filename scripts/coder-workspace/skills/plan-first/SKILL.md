# Plan First

For any multi-step task, write a short plan before executing. The plan is not
the deliverable — it is the map that keeps the work coherent.

## What the plan contains

- The goal in one sentence.
- The concrete steps in dependency order.
- The files or surfaces each step touches.
- The verification for each step (what command / output proves it worked).

## Rules

- Execute the plan; do not stop after writing it. A plan without execution is
  not completion.
- If a step reveals the plan was wrong, update the plan — do not silently drift.
- For a single, unambiguous task, do not over-plan: just do it.
- Keep the plan visible to the user so they can steer before you go far down
  the wrong path.
